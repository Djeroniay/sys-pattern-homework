# Домашнее задание к занятию "Репликация и масштабирование. Часть 2" - `Колодзеев Павел`

### Задание 1

1.1. Восстановление данных в полном объёме за предыдущий день

    Подходящие варианты резервного копирования:

    Полное резервное копирование (Full Backup)

    Выполняется ежедневно (например, в 23:00)

    Создаётся полная копия всей базы данных

    Хранится на отдельном носителе или в удалённом хранилищеВ случае простоя серверы обновляются по очереди, система остаётся доступной

    Рекомендация: полный бэкап + дифференциальный, так как восстановление быстрее, чем при инкрементном подходе

1.2. Восстановление данных за час до предполагаемой поломки

    Варианты резервного копирования:

    WAL-журналирование (Write-Ahead Logging) или Binary Logs

    Ведётся непрерывный журнал всех изменений в базе данных

    Позволяет восстановить данные на любой момент времени

    Журналы архивируются и хранятся отдельно от основной базы данных

    Рекомендация: комбинация полного бэкапа (ежедневно) + непрерывное архивирование WAL-журналов. Это позволяет восстановить базу на любой момент времени с точностью до минуты

1.3. Моментальное переключение на работающую базу при поломке

    Варианты реализации:

    Вариант 1: Репликация с автоматическим failover (кластер)

    Настраивается master-сервер и один или несколько slave-серверов

    Репликация работает в синхронном или полусинхронном режиме

    Используется инструмент мониторинга (например, Orchestrator, MHA, Patroni)

    При обнаружении сбоя master автоматически выполняется переключение на slave

    Время переключения: 5–30 секунд


    Вариант 2: Кластер с общей памятью (Shared Storage)

    Данные хранятся на общем дисковом массиве (SAN)

    Несколько серверов подключаются к этому массиву

    Активный сервер работает, пассивный ожидает

    При сбое активного пассивный мгновенно подхватывает данные

    Время переключения: 1–5 секунд


    Вариант 3: Синхронная репликация

    Запись выполняется одновременно на два и более сервера

    Данные всегда согласованы на всех серверах

    При сбое одного сервера другой уже содержит все актуальные данные

    Время переключения: 1–3 секунды


    Вариант 4: Готовый отказоустойчивый кластер

    Использование готовых решений: MySQL Cluster, Galera Cluster, PostgreSQL с Patroni, Oracle Data Guard

    Встроенные механизмы автоматического обнаружения сбоев и переключения

    Время переключения: 5–30 секунд (зависит от настройки)

### Задание 2

2.1. Примеры команд резервирования и восстановления
    Бэкап в текстовый SQL-файл:
    ``` pg_dump -U postgres -d mydb > backup.sql  ```
    Восстановление :
    ``` psql -U postgres -d newdb < backup.sql```
    Бэкап в кастомный формат (рекомендуется):
     ``` pg_dump -Fc -U postgres -d mydb > mydb.dump  ```
    Восстановление :
    ``` pg_restore -d newdb -U postgres mydb.dump```
2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?
    1. Планировщик CRON (Linux/Unix)
    2. Скрипт с полным циклом бэкапирования
    3. Готовые инструменты AutoPostgreSQLBackup

### Задание 3
3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.
    1. Полное резервное копирование с обновлением логов
    ``` mysqldump -u root -p --all-databases --single-transaction --flush-logs --master-data=2 > full_backup.sql```
    Восстановление:
    ```mysql -u root -p < full_backup.sql```
    2. Инкрементное копирование
    ``` mysqlbinlog --start-position=4 /var/lib/mysql/mysql-bin.000001 > incremental_backup.sql```
    Восстановление:
    ```mysql -u root -p < incremental_backup.sql```
